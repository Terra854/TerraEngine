# Advanced Production Animation Assets

This directory contains a small, coherent set of real cooked animation assets for
the animation production validation procedural, retargeting, motion-matching, ragdoll, recording, and
editor validation gates. The files are generated by
`Tests/Tools/Animation/AdvancedAnimationFixtureMaterializer.cpp` through the production
compilers and serializers. They are not renamed semantic JSON, generic dummy
envelopes, or hand-edited binary payloads.

## Asset relationships

GUIDs below are the 16 serialized GUID bytes written as 32 lowercase hexadecimal
characters. Fingerprints are persisted 64-bit compatibility values.

| File | GUID | Compatibility | Relationship |
|---|---|---|---|
| `source-humanoid.teskel` | `5445414e303433414456464958000001` | `0x043a000000001001` | Seven-joint source rig with an optional tail |
| `target-humanoid.teskel` | `5445414e303433414456464958000002` | `0x043a000000002001` | Eight-joint proportional target rig with leg detail and arm twist |
| `source-locomotion.teanim` | `5445414e303433414456464958000003` | Source skeleton fingerprint | Segmented root-motion clip with events, a recorded curve, and recording provenance |
| `target-recovery.teanim` | `5445414e303433414456464958000004` | Target skeleton fingerprint | Target-compatible get-up/recovery clip |
| `humanoid-retarget.teretarget` | `5445414e303433414456464958000005` | `0x043a000000007001` | Maps source to target with chains, contact, twist, and an explicit optional-tail fallback |
| `locomotion.temotiondb` | `5445414e303433414456464958000006` | Source skeleton fingerprint | Four structured samples in two streamable blocks referencing the source locomotion clip |
| `target-humanoid.teragdoll` | `5445414e303433414456464958000007` | Target skeleton fingerprint | Six primitive-collider bodies, five motorized constraints, partial blend data, and target recovery |

`manifest.json` pins every cooked asset's SHA-256, common-envelope content hash, byte
size, GUID, compatibility fingerprint, and serialized dependency table. It also
records the motion database's stable source-clip ID, the FNV-1a content
fingerprint used to invalidate source changes, the compiled retarget hash, and
the ragdoll recovery dependency.

## Reproduce and verify

First build the normal RelWithDebInfo engine library. Then run the following from
an x64 Visual Studio developer PowerShell at the repository root:

```powershell
$toolRoot = "out/validation/animation/fixture-tools"
New-Item -ItemType Directory -Force -Path $toolRoot | Out-Null

cl /nologo /EHsc /std:c++20 /MD /O2 /DNDEBUG /DWIN32 /D_WINDOWS `
	/DTERRAENGINE_SHARED /bigobj `
	/I. /IEngine /IEditor/AssetCompilers /IExternal/json/single_include `
	Tests/Tools/Animation/AdvancedAnimationFixtureMaterializer.cpp `
	Editor/AssetCompilers/AnimationClipCompiler.cpp `
	Editor/AssetCompilers/MotionDatabaseCompiler.cpp `
	out/build/RelWithDebInfo/TerraEngine.lib `
	/Fe:$toolRoot/AdvancedAnimationFixtureMaterializer.exe `
	/Fo:$toolRoot/ `
	/Fd:$toolRoot/AdvancedAnimationFixtureMaterializer.pdb

$env:PATH = "$(Resolve-Path out/build/RelWithDebInfo);$env:PATH"
& "$toolRoot/AdvancedAnimationFixtureMaterializer.exe" `
	"Tests/Fixtures/Animation/AdvancedAssets"
& "$toolRoot/AdvancedAnimationFixtureMaterializer.exe" `
	"Tests/Fixtures/Animation/AdvancedAssets" --verify-only
```

Generation stages every typed asset in memory, invokes each writer twice, checks
byte equality, deserializes the result, performs semantic validation, and
reserializes it before writing. Verification mode regenerates the complete
expected bundle in memory and compares it byte-for-byte with the checked-in
assets and manifest.

## Scope boundary

The ragdoll uses provider-neutral capsule recipes, so it has no missing convex
geometry or physics-cook dependency. It passes the full skeleton and
physics-policy validator. Creating Jolt bodies, applying impacts, blending the
live physics pose, and selecting recovery remain runtime behaviors for the
installed-editor gate.

IK has no standalone cooked asset type. The compatible skeletons and retarget
chains in this directory can support IK scenarios, but moving procedural goals
must come from a controller/runtime command during live validation.
